# VeriRun v0.5.0 — Distributed Executor

v0.5.0 delivers M4's bounded distributed-execution contract. Ray executes only
already-claimed immutable work; the v0.4 control-plane driver remains the sole
authority for durable leases and final results.

## Included

- Ray Data normalization and deterministic sharding of immutable durable task rows.
- Bounded Ray Core task and actor execution using `ray.wait`, custom named resource
  pools, and driver-side attempt/plan-lineage validation.
- CPU trusted-fixture local Ray and local kind/KubeRay RayJob references.
- Recovery fixtures for task and actor process loss, a transient driver-side final
  commit failure, a deterministic straggler, and observed Ray object spill.
- A logical 1/2/4/8/16 concurrency matrix, locked Ray dependencies, fixture image,
  KubeRay manifests, CI coverage, and the Ray Data/Core authority-boundary ADR.

## Evidence

The release assets contain the checked-in [M4 evidence report](../../evidence/v0.5/distributed/REPORT.md)
and its machine-readable summaries. The report binds the clean implementation
revision to the local Ray replay, two local kind/KubeRay baseline/replay RayJobs,
the local kind/KubeRay fault RayJob, fixture-image digest, Kubernetes identity,
KubeRay identity, and logical concurrency rows.

The evidence proves the frozen-plan, driver-only commit, lease-reclaim, and
bounded-cleanup contracts for CPU trusted fixtures. It does not establish hardware
capacity, a benchmark score, model capability, GPU availability, external-provider
reliability, multi-node behavior, or production operational reliability.

## Delivery semantics

- A worker or actor failure leaves the M3 lease reclaimable. Recovery uses a fresh
  attempt claim; Ray task retries and actor restarts are disabled for the fixture.
- Final-result authority is effectively once at the M3 durable commit boundary.
  Execution remains at least once.
- GPU inference and external API pools are named-resource admission contracts only;
  the release records no live evidence for either pool.

## Supported boundary

The distributed reference is limited to Python 3.12, Ray 2.50.1, KubeRay v1.4.0,
and one recorded local arm64 single-node kind cluster. The fixture image is pinned
to the recorded `python:3.12-slim` arm64 base digest and its release evidence
records the resulting local image digest.

## Known limitations

- This is not a production scheduler, HA, fault-tolerance, or capacity certification.
- The reference environment has no live GPU or external API verifier workload.
- No multi-node, autoscaling, cross-cluster, long-duration soak, or provider outage
  behavior is evidenced.
- Ray never selects verifiers, compiles plans, aggregates results, or writes durable
  control-plane state.

## Upgrade notes

The public package version changes from `0.4.0` to `0.5.0`. Existing protocol,
gateway, isolated-execution, and durable-control-plane paths remain available. To
install the optional M4 reference runtime:

```bash
python -m pip install -e '.[distributed-executor]'
make distributed-smoke
```
