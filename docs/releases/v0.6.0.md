# VeriRun v0.6.0 — Reliability & Evaluation Evidence

v0.6.0 delivers M5's evidence contract. It adds driver-side OpenTelemetry
correlation to the durable control-plane and bounded Ray paths, reliability validity
policy, and auditable paired statistics. Durable M3 plan, lease, artifact, and final
result records remain the source of truth.

## Included

- Correlated scheduler, worker-result, control-plane commit, M3 run-create, claim,
  and artifact-commit telemetry events with durable identifiers where available.
- First-attempt success, final success, retry amplification, failure-domain, latency,
  cost, and infrastructure-exclusion fields in a versioned reliability report.
- Automatic `valid`, `partial`, and `invalid` decisions for lineage and exclusion
  policy; a paired report separately marks insufficient samples or exclusions.
- Wilson 95% intervals for `pass@1`, pass@k without-replacement estimates, and a
  seeded paired bootstrap for `pass@1` deltas.
- `reliability-smoke`, a reproducible CPU trusted-fixture reference that combines
  M4 baseline/replay telemetry, recovery-chaos fixtures, logical concurrency, and a
  fixed paired-statistics fixture.

## Evidence and boundaries

The release evidence binds a clean implementation revision to the local CPU
trusted-fixture reference. It validates evidence mechanics and recovery behavior;
it does not score a model, establish an external-provider SLO, certify hardware
capacity, or demonstrate GPU, multi-node, HA, or production behavior.

The paired fixture intentionally contains fixed outcomes. Its statistical conclusion
therefore proves report implementation and invalidation policy—not comparative model
quality. The 1/2/4/8/16 values are logical scheduler configurations only.

On the recorded local Ray reference, recovery scenarios complete while a Ray spill
metric may be unavailable from the exporter. The evidence records that limitation and
does not turn absence of the metric into a spill or recovery claim.

## Upgrade notes

The public package version changes from `0.5.0` to `0.6.0`. OpenTelemetry API/SDK
1.44.0 are now core dependencies. For the local reference runtime:

```bash
python -m pip install -r requirements/distributed-executor-v0.5.lock.txt
python -m pip install -r requirements/reliability-evidence-v0.6.lock.txt
make reliability-smoke
```

Read [the reliability evidence guide](../RELIABILITY_EVIDENCE.md) for policy,
correlation fields, reproduction instructions, and limitations.
